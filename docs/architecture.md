# Архитектура сервиса подписки VPN (VLESS)

## Цель MVP

Сделать лёгкий сервис управления подписками для клиентов, которые умеют читать VLESS-ссылки из subscription URL.

## Выбранный стек

- **Go + stdlib HTTP** — быстрый, низкие затраты RAM/CPU, простой деплой.
- **SQLite** — дешёвое и надёжное хранилище для старта, без отдельного DB-сервера.
- **Server-side HTML templates** — минимальная нагрузка на фронт и сервер.

## Модули в MVP

1. **Админ-панель (`/admin`)**
   - создание и удаление пользователей;
   - ручная настройка одноразового ключа активации подписки;
   - создание и удаление VLESS-ключей;
   - drag & drop привязка ключей к пользователям;
   - управление лимитом устройств (HWID) для пользователя.

2. **Активация и Subscription endpoint (`/subscription`, `/sub/{subscription_id}`)**
   - пользователь вводит ключ активации на `/subscription` и получает URL подписки только один раз;
   - возвращает `text/plain` со списком `vless://...` ссылок пользователя;
   - при запросе `/sub/{subscription_id}` учитывает лимит устройств по HWID;
   - подходит как источник подписки для клиентских приложений.

3. **Слой данных (SQLite)**
   - `users`
   - `vless_keys`
   - `user_keys` (связь many-to-many)
   - `user_devices` (учет HWID пользователя)

## Рекомендованная структура для следующего этапа

- `internal/auth` — авторизация администратора (JWT/session/basic auth за reverse proxy).
- `internal/subscription` — форматы выдачи (plain, base64, JSON по необходимости клиентов).
- `internal/billing` — статусы подписок, сроки, авто-блокировка доступа.
- `internal/audit` — действия админа и журнал изменений.
- `internal/api` — REST API для интеграции с ботом/CRM/платежами.

## Что важно добавить перед продом

- Авторизация в `/admin`.
- HTTPS + домен для корректной работы клиентов.
- Ограничение rate limit на `/sub/{subscription_id}`.
- Резервное копирование `data/app.db`.
- Валидация формата VLESS и базовая санитизация пользовательского ввода.
